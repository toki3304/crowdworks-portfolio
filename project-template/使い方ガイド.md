# 案件用ひな形の使い方（toki用）

受注した案件を、毎回同じ手順・同じ品質で進めるためのひな形です。
このフォルダをコピーして使います。**このファイル（使い方ガイド.md）と CLAUDE.md は納品物に入れません。**

## 中身

| ファイル | 役割 |
|---|---|
| `CLAUDE.md` | Claude Code への毎回の約束事（日本語README、pytest、Windows対応、日本語エラー、データの扱い） |
| `requirements.md` | 要件メモ。受注したら最初に埋める |
| `main.py` | ツール本体のひな形。読み込み → 処理 → 書き出しの形と、日本語エラーが入っている |
| `tests/test_main.py` | テストのひな形。よくあるエラー（ファイルなし・列なし・空・数字でない）のテスト入り |
| `README.md` | 納品用の手順書。○○ と（ ）を埋めて使う |
| `requirements.txt` / `.gitignore` | ライブラリ一覧と、Gitに入れないもの（本番データ・鍵ファイル） |
| `sample_data/` | ダミーデータ置き場 |

## 案件ごとの手順

1. **コピーする**
   `project-template` フォルダをコピーし、案件名のフォルダ名に変えます（例：`2026-11_売上集計`）。
   ポートフォリオのリポジトリには入れず、パソコン内の別の場所で作業します。
2. **要件メモを埋める（15分）**
   `requirements.md` を、クライアントとのやり取りをもとに埋めます。
   クライアントの名前や本番データの中身は書かないでください。
3. **ダミーデータを置く**
   いただいたサンプルの列名だけまねて、中身は架空の値で `sample_data/` に作ります。
   Claude Code に「requirements.md の入力形式どおりのダミーデータを作って」と頼んでもかまいません。
4. **Claude Code に頼む**（そのまま貼り付けられます）
   ```
   requirements.md の要件どおりにツールを作ってください。
   CLAUDE.md の約束事を守り、main.py・tests・README.md を書きかえてください。
   終わったら python -m pytest と python main.py の結果を見せてください。
   ```
5. **自分で確認する（30分〜）**
   - `python main.py` を実行し、出力ファイルを開いて目で確認する
   - わざと空のファイルや列が足りないファイルを入れて、日本語のエラーが出るか見る
   - 分からないところは Claude Code に「この処理を初心者向けに説明して」と聞く
6. **途中で見せる**
   納期の半分くらいで、出力のサンプルをクライアントに見せて方向性を確認します。
7. **納品する**
   次の「納品前チェック」をすべて満たしたら、`CLAUDE.md` と `使い方ガイド.md` と `output/` を除いてzipにまとめて納品します。

## 納品前チェック

- [ ] `python -m pytest` がすべて通る
- [ ] 自分のパソコンで `python main.py` を実行し、出力を目で確認した
- [ ] クライアントのサンプルデータでも動いた
- [ ] README の ○○ と（ ）がすべて埋まっている
- [ ] `requirements.txt` に使ったライブラリがすべて書いてある
- [ ] 本番データ・鍵ファイル・個人情報が納品物に入っていない
- [ ] `CLAUDE.md`・`使い方ガイド.md`・`output/`・`__pycache__/` を除いた
- [ ] 納品メッセージに「納品後7日間は不具合に無料対応」と書いた
